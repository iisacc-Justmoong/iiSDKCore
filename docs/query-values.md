# 쿼리로 연결하는 반응형 값

## 계약

`QueryValue`는 소유자가 제공한 타입 지정 `QueryPort`에 값 읽기와 쓰기를
전달한다. 값의 실제 저장소와 유효성 검사, 요청의 의미는 소유 객체가 정한다.
뷰나 다른 소비자는 읽기 결과만 받으며 쓰기 요청은 해당 객체가 수락하거나
거부한다. 전송 실패와 소유자가 반환한 도메인 실패를 구분한다.

```cpp
// read는 QueryPort<ReadName, std::string>, write는
// QueryPort<WriteName, ii::core::Result<void>>이다.
ii::runtime::QueryValue<std::string, ReadName, WriteName> name{
    read, ReadName{}, write,
    [](std::string value) { return WriteName{std::move(value)}; }, changed};
```

`get()`은 선택된 읽기 쿼리를 전송하며 전달 실패 시 원래 `QueryError`를 가진
`QueryValueFailure`를 던진다. `set()`은 쓰기 요청을 생성하여 전송하고 소유자의
`Result<void>`를 그대로 반환한다. 전달 실패는 `closed`, `wrong_executor` 또는
`failed`로 구분하며 원래 쿼리 오류는 원인에 보존한다. 읽기 전용으로 노출하려면
`const QueryValue`를 사용한다. 수신기가 이미 확정한 변경과 변경 알림 실패를
구분하는 것은 소유자의 쓰기 계약이다.

변경은 소유자가 같은 실행 영역의 Core `Observable<uint64_t>` 변경 표식으로
명시적으로 발행한다. 표식은 값 저장소가 아니며 의존하는 소비자만 재질의하는
데 사용한다. 여러 값이 같은 표식을 쓰면 그 표식에 연결된 소비자가 함께
무효화되므로 선택적인 갱신이 필요하면 값을 구분한다. 매 프레임 재검사나
전역 이벤트 버스는 만들지 않는다. 누락 없이 변경을 발행하는 책임은 소유자에게
있으며, 임의의 C++ 대입을 자동 감지하지 않는다.
일반 C++ 메서드 안에서 `get()`을 호출해도 활성 Core 의존성 범위에 변경 표식이
기록되므로, 그 메서드의 소비자도 변경 시 필요한 값을 다시 조회할 수 있다.
변경 발행이 실패한 경우 소유자는 확정된 쓰기를 반복하지 말고 변경 표식을 다시
발행하거나 명시적으로 값을 재조회해야 한다.

포트·변경 표식과 이를 소유한 객체는 값 어댑터와 그 구독보다 오래 살아야
한다. 이 어댑터는 소유자의 상태를 복제하거나 소유권을 연장하지 않는다.
읽기·쓰기와 알림은 표식의 소유 실행 영역에서 처리한다. 다른 실행 영역의
작업은 Core의 큐 쿼리와 명시적 UI 전달을 사용한다. 동기 쿼리를 다른 실행
영역에 억지로 보내거나 실패한 쓰기를 자동 재시도하지 않는다.

LVUI는 이 값을 기존 읽기·쓰기 가능한 C++ 원본으로 취급하여 별도 뷰 문법
없이 기본 양방향 바인딩에 사용할 수 있다. 읽기 전용 원본과 명시적인 편집
명령은 기존 권한과 검증을 유지한다. 뷰 지역 `@State`는 각 활성화가 소유하는
임시 상태로 남는다.
