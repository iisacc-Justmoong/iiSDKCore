# Windows 아키텍처 검사

`tools/check_inheritance.py`는 실제 C++ 전처리 결과의 파일 위치를 추적하여 공개
레코드의 final 선언과 다중 상속 금지 정책을 검사한다. MSVC 출력은 같은 헤더의
`#line` 표식을 반복하므로, 한 번의 전처리 출력 안에서는 파일 경로 해석·검사
범위·파일 존재 여부를 파일 이름별로 재사용한다. 표식마다 경로를 다시 해석하던
Windows 병목을 제거하며 토큰의 줄 번호, 외부 헤더 제외 및 의존 파일 목록은
그대로 유지한다. 다음 번역 단위와 다음 실행에서는 위치 정보를 새로 계산한다.

`tests/architecture_policy.py`의 반복 표식 회귀 검사는 프로젝트/외부 헤더를
번갈아 방문하여 줄 번호·의존성·정책 위반이 보존되는지 확인한다. 전체 정책
검사는 테스트를 끈 빌드에서도 필수이며, 결과를 확인하지 않고 우회하지 않는다.

```powershell
python -B tests/architecture_policy.py
cmake --build build --config Release --parallel 4
ctest --test-dir build -C Release --output-on-failure
```
# Windows 프로세스 격리 회귀

상속 가능한 이벤트의 핸들 번호만으로 자식의 격리를 판정하지 않는다. 같은 숫자가
자식 내부의 다른 객체에 재사용될 수 있기 때문이다. 자식이 전달받은 번호의 이벤트를
설정하도록 시도한 뒤, 부모에서 원래 이벤트가 실제로 신호 상태가 되지 않았는지
확인한다. 런타임의 핸들 상속 제한은 그대로 검증하며 우연한 번호 충돌을 실패로
간주하지 않는다. 프로세스 실행·파이프·종료·자손 정리의 기존 검사도 함께 수행한다.
제한 없는 원시 Windows 생성 경로에서는 같은 fixture가 실제 상속 이벤트를 설정하는지
먼저 확인한 뒤 이벤트를 초기화한다. 따라서 fixture가 동작하지 않아 격리 검사가
거짓으로 통과하는 경우도 차단한다.
