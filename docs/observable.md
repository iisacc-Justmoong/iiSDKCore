# 소유 실행 영역의 타입 값 관측

`ii::core::Observable<T>`는 C++ 값과 단조 리비전, 소유 스레드의 명시적 `set()`을 제공한다.
일반 멤버 대입을 가로채거나 임의 C++ 객체를 자동 관측하지 않는다. `observe()`가 반환하는
`ObservableSubscription`을 보관하는 동안만 변경을 전달한다. 동등 비교를 제공하는 값이
같으면 리비전과 통지가 없으며, 속성 소멸과 구독 해제는 이후 통지를 차단한다.

`observe()`는 읽기 전용 참조에서도 사용할 수 있다. 구독의 접수·해제는 값의 수정 권한을
제공하지 않으며 `const Observable<T>`에는 `set()`을 호출할 수 없다. 값·revision은 구독
등록으로 바뀌지 않는다. 같은 소유 스레드에서만 읽기·구독할 수 있으며 이동된 이전 객체와
소멸한 소유자의 구독은 기존 종료 규칙을 유지한다. 내부 공유 상태에 관측자 lease를
등록하므로 `const_cast`나 상위 GUI 모듈의 어댑터를 요구하지 않는다.

값은 복사 생성과 예외 없는 이동 대입을 제공한다. `operator==`가 있는 값은 같은 값을
설정할 때 발행하지 않는다. 동등 비교가 없는 C++ 값도 받을 수 있으며, 이 경우 각
`set()`을 명시적인 변경 발행으로 처리한다. 동등 비교가 없는 대상을 가리키는
`reference_wrapper`도 이에 해당한다. 비교 가능한 대상의 표준 참조 래퍼는 C++ 비교
규칙을 따른다. 참조 대상의 외부 대입을 자동 발행하지 않으며 필드 반사나 주소 기반의
임의 동등성을 추측하지 않는다. 참조 값의 실제 대상은 기존 소유자가 계속 소유해야 한다.

재진입 변경은 값·리비전 스냅샷 순서로 전달한다. 통지 중 추가한 구독은 다음 변경부터 받고,
먼저 해제한 구독은 같은 변경의 남은 전달에서도 제외된다. 관측자 예외는 다른 관측자의
전달을 끝낸 뒤 호출자에게 전달한다. 이미 커밋한 값과 리비전은 예외로 되돌리지 않는다.

하나의 전달 과정에 256개 변경, 1,024개 관측자를 허용한다. 순환 갱신은 다음 값의 커밋 전에
`length_error`로 거부한다. 외부 스레드의 값 접근/변경은 `logic_error`이다. 작업자 결과는
기존 Runtime/UiExecutor로 소유 스레드에 전달해야 한다.

LVUI AOT는 이 계약을 직접 C++ 구독과 위젯 갱신으로 생성할 수 있다. Core는 UI 언어,
위젯, LVRS나 GUI에 의존하지 않는다. `iiSDKCore.Observable`은 no-op, 재진입 순서, 해제,
소멸, 예외, 다른 스레드와 갱신 순환의 한도를 검사한다.

## C++ 읽기 범위 수집

`ObservableReadScope::collect(collector, function)`은 해당 동기 함수가 `Observable::get()`으로
읽은 원본을 수집한다. 일반 C++ getter 내부의 private Observable도 필드를 노출하거나
문자열로 반사하지 않고 의존 원본으로 연결할 수 있다. 현재 실제 소비자는 LVUI의 네이티브
메서드·함수 호출이다. Core에는 UI 언어·뷰·의존성 그래프를 추가하지 않는다.

`ObservableRead`는 안정적인 상태 식별자, 읽은 revision, 구독과 최신 revision 확인 함수를
제공한다. 상태와 공유 포인터 payload의 읽기 당시 소유권도 보존한다. 속성 객체가 이동해도
같은 상태를 가리키며, 원본이 닫히면 조회·새 구독을 거부한다. 상태를 보존한다고 닫힌
객체에 대한 사용 권한이 되살아나지는 않는다. `read_dependency()`로 같은 기록을 명시적으로
얻을 수 있으며, 원시 속성 객체 주소를 나중에 역참조하지 않는다.

수집은 현재 스레드의 가장 안쪽 범위에만 전달한다. 콜렉터 자체가 읽은 값은 다시 수집하지
않으며 `pause(function)`은 동기 하위 호출의 수집을 명시적으로 가린다. 함수나 콜렉터가
예외를 던져도 이전 범위를 복구한다. 반환값·참조·C++ 복사 생략을 유지하며, 범위나 새
작업 스레드를 반환·생성하지 않는다. 작업자 스레드로 수집 환경을 자동 전달하지 않는다.
범위 깊이는 최대 64개이며 초과는 실행 전에 `length_error`로 거부한다.

이 수집기는 전역 객체 등록소나 변경 통지 버스가 아니다. 명시적으로 연 동기 범위에서만
작동하고 일반 멤버 대입·외부 라이브러리의 임의 내부 상태는 추적하지 않는다. 실제 구독,
중복 제거·의존성 교체·재계산·실패 처리와 실행 영역 연결은 소비자가 소유한다.
`iiSDKCore.ObservableReads.*`는 실제 getter, 중첩·중지·예외·수명·이동·스레드·깊이·
비이동 값 반환을 검사한다.

### 공유 관측 실행부

관측을 사용하는 소비자는 `iiSDKCore::Observation`을 명시적으로 연결한다.

```cmake
find_package(iiSDKCore CONFIG REQUIRED COMPONENTS Observation)
target_link_libraries(model PRIVATE iiSDKCore::Observation)
```

이 작은 표준 C++ 실행부가 스레드별 수집 포인터·깊이·진입·복구를 소유한다. 앱과 숨김
공유모듈은 같은 실행부를 사용하므로 모듈마다 별도 TLS가 만들어지지 않는다. Hosted
macOS·Windows·Linux·Android에서는 공유 라이브러리로 구성하고, 정적 등록을 사용하는
iOS·WASM에서는 단일 실행 이미지에 정적으로 연결한다. `BUILD_SHARED_LIBS=OFF`로 큰
Runtime을 정적으로 빌드해도 hosted 관측 실행부는 공유한다. 동적 모델과 앱이 서로 다른
Core 패키지 사본을 사용하지 않도록 배포할 때 이 의존성도 함께 포함해야 한다.

`Observation`은 `Contracts`와 C++ 표준 라이브러리만 참조한다. 작업자 Runtime·Threads
패키지·GUI·제품 모델을 요구하지 않는다. `Runtime`은 관측 실행부를 공개 의존성으로
포함하며, `Contracts`만 찾는 소비자에게는 관측 라이브러리도 가져오지 않는다. 관측
헤더의 값 계약은 읽을 수 있으나 `Observable::get()`·읽기 수집을 실행하려면 해당
구현 타깃을 연결해야 한다. 구현이 없는 예전 Core 패키지는 LVUI 구성 단계에서 거부한다.

이전 헤더의 `inline thread_local` 방식에서는 반환값 6→10은 정상이나 모듈 내부 수집이
비활성이 되어 읽기·통지 0건인 문제를 재현했다. 당시 기록은
`build/observation-module-before-20261026.log`와 `build/lvui-methods-boundary/`에 보존한다.
수집 1건·변경 통지 1건의 기존 수용 조건을 유지하며 `iiSDKCore.ObservableModuleBoundary`
및 중첩·예외·스레드·깊이·종료 검사에서 공통 실행부를 검증한다. 설치·재배치 소비자는
같은 숨김 모듈과 헤더 전용 Contracts의 독립성을 각각 확인한다.
